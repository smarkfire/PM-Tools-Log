## v1.0.0 · 首次部署（2026-09）

系统初始版本，包含以下功能：

- **用户体系**：注册 / 登录（JWT 鉴权）、个人资料、修改密码、全局角色四级体系（项目总监 / 项目经理 / 小组长 / 组员）
- **项目管理**：项目 / 小组 / 成员管理，四级数据权限（总监看全部、经理看所辖项目、组长看本组、组员看自己）
- **工作日志**：每日填写、AI 优化（通义千问 / DeepSeek 双通道）、日志列表查看
- **报告中心**：个人 / 项目周报、月报 AI 生成
- **AI 助手**：基于权限范围内日志数据的智能对话
- **提示词**：系统默认 + 用户自定义提示词，三级优先级
- **AI Key 配置**：用户自配 Key > 系统配置 > 服务器环境变量
- **其他**：管理员全局菜单开关、响应式前端（桌面 / 移动）、演示数据、幂等建库脚本

## v1.1.0 · 第二次部署（2026-10-16）

### 一、新增功能

#### 1. 收件箱与消息提醒
- 新增收件箱页面，集中查看站内消息（版本更新、审批结果、反馈回复）
- 顶栏新增消息提醒图标，实时显示未读数角标（60 秒轮询），点击直接跳转收件箱

#### 2. 跨周修改审批 + 审批中心
- 本周内填写的日志 / 报告可自由修改
- 本周以前的日志 / 报告需先提交修改申请，经上级领导审批（通过后仅可修改一次）
- 审批层级：组员 → 组长 / 项目经理审批；组长 → 项目经理审批；项目经理 → 项目总监审批
- 新增审批中心菜单，审批结果自动站内通知申请人

#### 3. 意见反馈
- 用户可提交使用意见（可留联系方式）
- 管理员查看、回复并标记已处理，回复后自动通知反馈人

#### 4. 版本管理与更新通知
- 管理员可在系统设置中发布新版本（版本号 / 标题 / 更新说明）
- 发布后自动向全员收件箱推送更新通知，历史版本可查、可删

#### 5. 系统管理员角色 + 角色菜单可见性
- 新增"系统管理员"全局角色，与项目总监同等系统权限（全数据、用户管理、系统设置、审批豁免）
- 新增"角色菜单可见性"配置：管理员按角色（总监 / 管理员 / 经理 / 组长 / 组员）控制每个菜单是否可见
- 取代原"功能菜单开关"（全局开关），菜单可见性管理更精细

#### 6. 跨组协作
- 一名成员可同时加入多个小组（原来每人只能属于一个组）
- 填写日志可多选"涉及小组"，并为各小组分配投入工时（默认按总工时均摊，可手动修改）
- 校验：各小组工时之和不能大于当天总工时（前端实时提示 + 后端强校验）
- 所辖小组被标记的日志，组长也可见（跨组协作数据权限）
- 项目报告按小组分节统计

#### 7. 报告自定义日期范围
- 报告生成支持两种模式：默认按基准日期自动推算周期，或切换为自定义任意日期范围

### 二、优化与调整

- **日志列表**（桌面表格 / 移动卡片 / 详情弹窗）：
  - 表头"日期"改为"日志日期"，格式统一为年月日
  - 末尾新增"数据时间"列，展示日志的创建时间（年月日时分秒）
- **填写日志**：
  - 日期可选本周任意一天（原仅限当天），跨周日期不允许新建
  - "所属项目"改为必填
  - 所有用户填写日志时均可选择涉及小组
- **Markdown 渲染统一**：日志、报告详情、AI 对话统一使用 Markdown 渲染（禁用 HTML 防止 XSS）
- **个人信息**：新增邮箱字段编辑
- **安全**：修改密码强制强密码校验——8~64 位且至少包含大写字母 / 小写字母 / 数字 / 特殊字符中的三类（前后端一致）

### 三、行为变化（老用户请注意）

| 变化 | v1.0.0 行为 | v1.1.0 行为 |
|---|---|---|
| 历史日志删除 | 本人日志随时可删 | **本周以前的日志永久不能删除**（任何角色，含总监 / 管理员） |
| 历史日志修改 | 本人日志随时可改 | 本周以前的日志必须**审批通过后**才能修改（且仅一次） |
| 菜单可见性配置 | 系统设置 → 功能菜单开关（全局） | 系统设置 → 角色菜单可见性（按角色），原全局开关配置不再生效 |
| 日志新建日期 | 仅当天 | 本周一至今天任意一天 |

### 四、数据库变更（运维注意）

相对 v1.0.0 新增 6 张表、7 个索引，不修改既有表数据：

| 新增表 | 用途 |
|---|---|
| `project_group_members` | 成员多小组（跨组协作） |
| `work_log_groups` | 日志多小组标记 + 各组工时 |
| `edit_approvals` | 跨周修改审批 |
| `feedback` | 意见反馈 |
| `app_versions` | 版本记录 |
| `notifications` | 收件箱通知 |

另有清理项：废弃的全局菜单开关键（`menu_*`）从 `system_config` 中移除（v1.1.0 已改为按角色的 `role_menus` 配置，无需预置，未配置时默认全部菜单可见）。

### 五、升级操作步骤（v1.0.0 → v1.1.0）

```bash
# 1. 备份数据库（必做）
pg_dump -h <主机> -U <用户> -d <数据库名> -F c -f backup_v1.0.0_$(date +%Y%m%d).dump

# 2. 执行数据库升级脚本（幂等，可重复执行）
psql -h <主机> -U <用户> -d <数据库名> -f server/sql/upgrade_v1.0_to_v1.1.sql

# 3. 部署 v1.1.0 代码（对应 Git 标签 v1.1.0）
git checkout v1.1.0   # 或拉取 main 分支最新代码

# 4. 重启服务，验证登录、填写日志、收件箱功能正常
```

升级脚本执行后的自查：脚本末尾附有校验 SQL，执行后应返回 6 张新表。

### 六、部署后建议（可选）

部署完成后，管理员可在 **系统设置 → 发布新版本** 中录入本版本的更新说明（可直接复制本文档"一、新增功能"和"二、优化与调整"部分），系统会自动向全体用户的收件箱推送本次更新通知。

## v1.3.0 · 第四次部署（待部署）

### 一、新增功能

#### 1. 新版填报日志（新旧填报页并存，先部分用户试用）
- **三块布局**：左侧"今日待办"、中间"对话与质量检查"、右侧"优化后的日志"
- **今日待办**：类似 checklist 的待办管理（添加 / 勾选完成 / 删除），按日志日期保存归档
- **对话式生成**：点击"根据待办生成日志"，AI 结合待办执行情况与补充说明自动起草
- **AI 质量检查（多轮澄清）**：AI 按"好日志规范"逐项核对，凡有缺失或含糊之处，在对话框里向用户提问或给出选项让用户选择；补全后重新检查，直到信息足够才输出最终稿；检查过程与提问全程在对话框可见
- **好日志规范结构**（一级=谁哪天的日志 → 二级=项目/明日计划/问题风险 → 三级=小组）：

  ```markdown
  # 2026-11-07 张三 的日志
  ## 项目名称：{项目名称}
  - 投入时长：X小时
  ### 小组名称：{小组名称}
  - {功能模块/交付物}：做了什么，有什么成果
  ## 明日计划
  - …
  ## 问题与风险
  - …
  ```

  要点：投入时长写在项目下（小组下不再写工时）；每条事项必须写清**哪个功能模块或哪个交付物**做了什么工作
- **用户确认后保存**：右侧可编辑 / 预览最终稿，确认后直接保存（待办执行情况存为原始内容，AI 定稿存优化内容，与报告生成链路打通）
- **一天一条日志，不再选择项目**：保存时不再弹出"选择项目"；一天可能涉及的多个项目全部作为内容写进日志（`## 项目名` 二级标题），日志表 project_id 允许为空
- **项目/小组名称核对**：AI 生成与质量检查时自动注入用户实际参与的项目与小组清单，日志中的项目名、小组名必须与项目管理数据完全一致（不得用别名、简写或自创名称），保证后续按项目、按小组归集生成报告不出错
- **AI 质检得分入库**：每条新版日志的 AI 质量检查得分（0~100）随保存写入日志表 `ai_score` 列，日志列表中以分数徽章展示（≥80 绿 / ≥60 橙 / <60 红）
- **保存前二次质检**：点击"质检并保存"后 AI 先对日志终稿复检（只打分不改写），弹窗展示分数、总评与具体修改建议，用户确认"保存"或"返回修改"；质检接口异常时可选择跳过直接保存；**保存进日志表的得分以二次质检分数为准**
- **质检问答控件升级**：AI 追问环节按问题类型自动匹配控件——项目名称 / 小组名称缺漏时改为从"我参与的项目 / 小组"**下拉选择**（与项目管理数据同源，杜绝手写错名），项目与小组**单选且联动**（小组候选随所选项目过滤）；工时用**数字步进控件**（0~24，步长 0.5）；需要自由输入文字的问题改为**多行文本框**
- **页面精简**：填报页去掉"我的日志"按钮（日志统一在"我的日志·新版"查看）
- **页面细节**：日期选择、模型选择与页面标题同行排布；整页不滚动，滚动收纳在对话区内部
- **试用方式**：旧版"填写日志"原样保留，侧边栏新增"填写日志·新版"入口，线下安排部分用户试用；试用结束后再推广全员（不涉及系统级开关）

#### 2. 历史待办
- 新增"历史待办"菜单：按日期倒序查看以前每天填写的待办清单与执行情况（完成进度条 + 展开明细），保留近 60 天

#### 3. 我的日志·新版（新版日志列表）
- 新增"我的日志·新版"菜单：专门展示对话式填报（v2）产生的日志，原"我的日志"原样保留
- 支持 **卡片** / **列表** 两种查看方式，一键切换并记住用户选择
- 卡片视图：日志日期、AI 得分徽章、涉及项目标签（从日志内容自动提取）、内容摘要、工时、AI 模型、数据时间；卡片左侧色条按得分着色，尺寸统一对齐
- 列表视图：日志日期、得分、工时、内容摘要、AI 模型、数据时间（项目信息在内容中，不再单列）
- 点击卡片或行打开详情弹窗：Markdown 渲染日志定稿、AI 得分、涉及项目一目了然，原始记录（待办执行情况）可折叠查看；详情内可 **预览 / 编辑** 切换直接修改内容保存
- **操作能力与旧版对齐**：卡片与列表操作列提供 **查看 / 编辑 / 审批中 / 申请编辑 / 删除** 三态按钮——本人本周日志可直接编辑删除，跨周编辑需提交审批（审批中禁用按钮，通过后限改一次），总监不受限
- 支持按日期范围、关键词筛选与分页

#### 4. 项目报告支持按小组生成
- 生成项目周报/月报时可选择小组（可选），为该小组单独生成一份报告；报告列表与详情中显示"项目 · 小组"
- 小组归属规则：v2 日志按内容"### 小组名称：xxx"标题归组；v1 日志按显式小组标记；未标记的 v1 日志回退到作者小组成员身份
- **项目报告数据归集增强**：v2（对话式）日志的项目信息在内容中（project_id 为空），此前项目报告会漏掉 v2 日志——现按"项目成员 + 内容『## 项目名称：xxx』标题"统一归集，v1/v2 日志全部纳入
- 提示词增强：生成报告时自动注入【日志数据结构说明】（标准模板层级、项目名称/小组名称带固定前缀、投入时长位置），AI 严格按标题归集项目、小组与工时，名称保持日志原文不得改写；系统默认报告提示词随部署自动更新
- 按小组分组的整体项目报告同样识别 v2 日志的小组标题，工时按涉及组数均摊

#### 5. 旧版日志页面与新规范对齐
- **填写要点升级**：旧版"填写日志"的填写要点从内容框上方的折叠面板改为**页面标题旁的悬浮说明图标**（悬停弹出，内容与新版完全一致：标准日志模板 + 事项写法公式 + 评分构成）
- **AI 优化准则更新**：旧版"AI 优化日志"改以**新版标准日志规范**为优化准则——输出严格遵循标准模板层级（`## 项目名称：xxx` / `### 小组名称：xxx` / 明日计划 / 问题与风险），事项按"进展 + 对象 + 动作 + 成果"公式整理；优化时自动携带姓名 / 日期 / 所选项目 / 涉及小组 / 投入时长上下文，缺失字段写"（待补充）"不编造；`log_optimize` 系统提示词种子随部署自动更新（升级 SQL 同步纳入）
- **表单布局调整**："日志日期 + 工作时长"一行、"所属项目 + 涉及小组"一行；**取消按小组分配工时**（小组仅作涉及标记，工时统一记当天总投入）
- **我的日志列表双视图**：旧版"我的日志 / 团队日志"列表新增 **卡片 / 列表** 切换（与新版一致）——卡片含日志日期、得分徽章、项目/成员标签、摘要、工时、AI 模型与三态操作按钮（查看 / 编辑 / 审批中 / 申请编辑 / 删除），左侧色条按得分着色，选择自动记忆；移动端固定卡片

### 二、数据库变更

- `reports` 表新增 `group_id` 列（记录项目报告指定的小组，幂等迁移自动添加，历史报告不受影响）

- `work_logs` 表新增两列（由部署时幂等迁移自动添加，历史日志自动归为 v1，不影响任何已有数据）：
  - `source`：日志来源（v1 旧版填报 / v2 新版对话式），用于新旧日志列表分流
  - `ai_score`：AI 质量检查得分（0~100，新版日志保存时记录）
- 新增 `todo_items` 待办表（user_id / todo_date / content / status / sort_order，按日整份替换保存），由部署时幂等迁移自动创建，**不影响任何已有数据，历史日志完整保留**
- 新增 `log_review` 系统提示词种子（好日志规范 + 质量检查规则 + 项目/小组名称核对要求），首次部署自动写入、升级部署自动更新
- `log_optimize` 系统提示词种子更新为新版标准日志模板优化准则，并纳入部署自动更新范围（log_optimize / log_review / report 三类随部署自动更新，不覆盖用户自建提示词）
- 从 v1.2.x 升级：部署代码即可，无需手动执行 SQL（如需手动执行，可运行 `server/sql/upgrade_v1.2_to_v1.3.sql`）

### 三、问题修复

- **修复两次质检分数不一致的问题**：此前日志内容未修改，保存前二次质检的分数也可能比生成时质检低——根因是大模型评分存在随机性、且复检提示导致"额外从严"。现改为**确定性评分**：质检接口 temperature 固定为 0，评分必须在思考中**逐项计算**（结构层级 10 + 投入时长 10 + 明日计划 10 + 问题风险 10 + 事项质量 60，求和），提示词明确"同一篇日志只要内容相同，无论评多少次（包括二次质检）都必须得到相同分数，不得因复检而额外从严"；`log_review` 系统提示词种子随部署同步更新
- **修复日期显示为原始时间戳的问题**：历史待办的日期、报告中心的周期列与详情周期此前显示 `2026-11-08T00:00:00.000Z` 原始格式，现统一格式化为 `2026-11-08`
- **我的日志·新版头部美化**：卡片/列表切换与"填写日志"按钮（原"去填写"）移至页面标题右侧同行展示，不再挤在描述下方
- **报告生成小组下拉联动明确化**：小组选项严格随所选项目联动；项目下没有小组时下拉置灰并提示"该项目下暂无小组"；演示数据为大模型项目补建算法组/应用组，两个演示项目均有小组可选
