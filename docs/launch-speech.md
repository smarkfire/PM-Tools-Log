## 产品揭幕（5 分钟）

【大屏切到 Logo，主标题 + 副标题"每天 5 分钟，周报月报自动生成"】

大家看这个名字。"脉络"——我们常说"理清脉络"，中医里讲，脉络是气血运行、连通全身的网络。放到一个团队里，**每个人的日志就是一条细小的脉络，汇聚到一起，就是这个组织的经营脉络。**

它到底是什么？一句话：**一个让你把流水账写进去、专业日志和周报自动出来的团队日志系统。**

它有四个我们最在意的设计原则，我先讲给管理层听：

1. **真实**——日志记录的是事实，不是作文。
2. **省力**——你会写的只是大白话，AI 帮你整理。
3. **可信**——写过的日志有纪律约束，改和删都有规则，经得起审计。
4. **自动汇报**——同一批日志，一份给领导、一份给甲方、一份给集团，口吻完全不同，一键生成。

【快速过一句话：我们是给团队用的工具，不是给个人记日记的工具，所以"权限"和"纪律"我们想得很多，一会儿专门讲。】

## 核心 Demo（8 分钟）

> 【大屏切到线上系统，提前登录好总监账号 director1，数据已灌好】

空口无凭，我们直接看真实系统。

### Demo 1：流水账 → 专业日志（2 分钟）

【切到"填写日志"页，输入一段口语化内容，例如：】
"上午开了需求评审会，把 V2.0 的三个功能定了，下午写用户模块接口，自测过了，还帮小王看了一个线上 bug。"

大家看，这就是我们一线同学**每天的真实状态**——想到哪写到哪。

点一下 **AI 优化**。

【点击，等 1~2 秒出结果】

现在它变成了什么？三段式：**今日完成 / 问题与解决 / 明日计划**，还自动把"帮小王看 bug"提炼成了一个个可追溯的成果项。

**关键点：AI 只整理措辞，从不编造数字。** 事实是你填的，它负责让它"像样"。这也是我们对 AI 的边界。

### Demo 2：一个人干三组的活，一篇日志搞定（3 分钟）

【切到"涉及小组"多选，演示一个人同时标记前

端组、后端组、数据组，并分配工时 4/3/1】

很多人问我们：**"一个人同时干几个组的活，要写几篇日志？"** 我们的答案是——**一篇。**

一篇日志，可以同时标记多个小组，还能**分别分配各组投入的工时**。谁干了多少、哪组摊了多少，清清楚楚。到月底统计的时候，每个小组的投入是准的。

这也是为什么我们说它是"团队的脉络"——**日志进来了，它会自己流向该去的地方。**

### Demo 3：同一批数据，四份周报（3 分钟）

【切到报告页，选本周，展示四个报告模板：公司领导周报 / 甲方项目组周报 / 集团管理部门周报 / 公司简报】

这是今天**最该让管理者睁大眼睛的一幕**。

同样的日志数据，我们准备了**四种不同的汇报口吻**：

- 给**公司领导**的——一页以内，只讲里程碑、风险和要拍板的决策。
- 给**甲方**的——计划对实际，按模块分组，交付物可核查。
- 给**集团管理**的——规范严谨，指标全部表格化。
- 给**公司简报**的——三百来字，有温度、有团队风采。

【现场各点一下，展示四份排版差异】

各位算一笔账：**过去这四份周报，是不是四个人、各花了半天？现在，2 分钟。**

## 数据权限与可信（5 分钟）

【切到权限说明页或白板示意四级结构】

刚才我们一直在讲"自动""省事"，但我必须认真讲一件管理层最该关心的事：**纪律。**

我们把数据权限分成了**四级**：

> 总监 / 经理 / 组长 / 成员，各自只能看自己该看的那份数据。

更关键的是两条**铁律**，这也是系统和"随便记个笔记"最本质的区别：

1. **本周之前的日志，不能删除。** 永久留痕。
2. **本周之前的日志要改，必须上级审批。** 改了什么、为什么改，走审批流程，全程可查。

【停顿，环视】

为什么这么设计？因为**一本能被随手改来改去的日志，是不值得信任的；而一份值得信任的日志，才配叫做团队的资产。**

## 迭代路线（3 分钟）

【大屏放出版本时间线：v1.0 → v1.1 → v1.2】

最后，简单说说我们从哪来、往哪去。

从第一个版本到今天，我们已经迭代了三版，每一次都是**跟着真实团队的反馈**改的：

- **v1.0**——把日志、项目、成员、周报月报的基础闭环跑通。
- **v1.1**——补上四级数据权限、跨组协作、报告自定义时间范围。
- **v1.2**——正式定名 **MateLog 脉络**，加入角色提示词和多种报告口径。

这说明一件事：**它不是一次性的玩具，而是一套在真实使用中持续进化的工具。**

## 附：现场问答预案

| 可能被问 | 回答要点 |
|---|---|
| "AI 会不会乱改我的日志？" | 不会。AI 只整理措辞，事实和数字必须用户填充；优化前后原文都在，可对比。 |
| "数据安全吗？" | 数据存在自己的数据库，权限分级管控，历史日志不可删、改需审批，可审计。 |
| "一个人干多个组怎么办？" | 一篇日志多组标记、按组分工时，无需重复填写。 |
| "要装什么？" | 网页即用，浏览器打开即可，无需装客户端。 |
| "能不能和现有 OA 打通？" | 可作为独立工具先用起来，接口层面可后续规划对接。 |
